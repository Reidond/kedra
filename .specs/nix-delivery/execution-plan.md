# Execution plan

Session counts are a decomposition, not an estimate.

Five Astra read-only scouts completed disjoint feature inspection. Their claims
are inputs to implementation and are not runtime passes. Source reading found
the real blockers: VM composition refusal, ARM-only engine/replay, main-only
production signing, absent production catalog and unleased SIGKILL snapshots.

One integrated implementation layer and one heavy runtime sequence at a time.
Up to three preparers may write new unregistered files that neither compile nor
execute in the active layer. They must not register modules/tests, edit shared
metadata or run cargo/build/Docker/VM operations. Parent integrates those files
only on the owning layer. No linked worktree is needed.

The cap is derived from: one shared branch/index and shared module/manifest
chokepoints; one retained daemon, native runtime and bounded host storage; seven
available agent slots. Five concurrent scouts are safe/read-only; one integrated
writer, three disjoint new-file preparers and one spec-only writer fit those slots
with the parent and a read-only critic. Integrated heavy qualification is serialized.
Usage/time windows are not a
duration forecast; checkpoint scope/evidence at every layer boundary.

| Context | Worker role | Output / boundary |
|---|---|---|
| D1 implementation | Astra judgment | VM bridge, artifact observers, actual named disposable boot/restart/screenshot; frozen before source gates. |
| D2 implementation | Astra judgment | ARM foundation/composition runner and unchanged signer contract; actual fixture install/update/rollback. |
| D3 preparation/integration | Astra judgment | New pure catalog modules and pinned sources, later actual nonroot builds/candidate exposure. |
| D4 preparation/integration | Astra judgment | External executable using public catalog/engine directly; later actual cross-store/policy/rollback/GC workflows. |
| D5 implementation | Astra judgment | Authenticated pre-admission constraints and lock-backed temporary leases; native faults and bounded filesystem ENOSPC. |
| Parent each boundary | Codex | Integrate/review, pin executable hashes per invocation, verify actual gates, commit/submit/attach exact PR. |

No subagent may stage/commit/switch branches, update global/personal tooling or
sign/publish production material. Source/API transitions are announced before
dependent work resumes. Pinned controller copies prevent Cargo feature/build
variants from replacing a qualification executable. Hash before/after every
fault and replay; no retrospective same-artifact claim.

Preserve active default VM/container and owner media. New VM names/volumes/
credentials have exact ownership records; remove only owned disposable resources.
Run host Python through uv, guest Python only with an explicit environment header.
Only existing public CLI and sanctioned container/native VM workflows; no custom
runner, source scanners, unit/mock/model/doctests.
