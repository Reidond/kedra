# Fedora package checks

Resolve only the reviewed official Fedora 44 Linux stream, for the target's own OCI architecture (amd64 for desktop, arm64 for qemu-arm64, no variant), to an immutable digest. Each target resolves and builds natively on its own runner; `usr/src/kedra/image/inputs.json` schema 2 pins one bootc-image-builder manifest per architecture (2026-09-25). Reconcile the complete installed native package closure with stable fedora/updates repositories and signature verification. Use fresh metadata and bypass cached package layers. Missing repositories, invalid RPMs or solver failures are errors.

Resolve the RPM sets once per run with `sysroot catalog lock resolve` into an RPM lock (every installed RPM: NEVRA, SHA-256, Koji signed-copy URL and the mirror URL used) whose files become fixed-output engine store objects. Every later build in the run installs offline from those objects (`catalog/install-rpms.sh`, `--disablerepo='*'`, `localpkg_gpgcheck`), so a mirror push mid-run cannot change the image. Compare source, base, artifacts, recipes and the lock's pins hash (`artifacts['rpm-lock']`, the lock without mirror URLs) against the signed stable image's resolved-input record. Same package version is not proof of same bytes. The built image's installed inventory must equal the lock.

Facts (2026-10-14, Fedora 44, dnf5 5.4.6, rpm 6.0.2): Koji `packages/<srpm-name>/<v>/<r>/<arch>/<file>` serves the unsigned RPM (other SHA-256 than mirrors); the signed copy mirrors serve is `packages/<srpm-name>/<v>/<r>/data/signed/<keyid8>/<arch>/<file>` (F44 key `6d9f90a6`), byte-identical to a mirror for jq-1.8.1-3 and gnome-keyring-pam-50.0-1. Offline dnf5 with `localpkg_gpgcheck` refuses ("repository does not have any OpenPGP keys configured") until `rpmkeys --import /etc/pki/rpm-gpg/RPM-GPG-KEY-fedora-44-primary`. Offline `--network none` install of the qemu-arm64 lock (894 RPMs, 906 MB) reproduces the online seven-column inventory exactly. `dnf5 history undo last` of a builder transaction on the bootc foundation aborts (libdnf5 `State::set_package_reason` assertion, reason "None" for image-installed packages), so builder roles never undo in place: the last role uses the foundation container, earlier ones a commit of it.

At 00:00 UTC or an optional on-demand run, changed inputs produce a candidate for automatic isolated OCI signing and verified stable publication. No human approval is required. No-change does nothing: no ISO, GitHub Release, metadata asset or freshness checkpoint. Queued/disabled schedules are not proof of current inputs.

Keep exact provenance in the signed image. Never mirror all Fedora, automatically commit nightly package versions or weaken native signature/solver checks.

Sources: [GitHub schedules](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [DNF5 upgrade](https://dnf5.readthedocs.io/en/latest/commands/upgrade.8.html), [RPM verification](https://rpm.org/docs/6.0.x/man/rpmkeys.8). Verify actual native versions rather than assuming latest documentation matches the image.
